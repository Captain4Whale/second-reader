# Source Of Truth Map

Purpose: map important project information to one canonical location, one optional machine-readable companion, one validation command, and one update trigger.
Use when: deciding where durable information belongs or checking whether a handoff/state update was written to the right place.
Not for: product behavior, API semantics, or temporary session scratch notes.
Update when: canonical storage locations, machine-readable companions, validation commands, or update triggers change.

This workspace is repo-first. Chat, Notion, and other tools may incubate work, but they are not authoritative for current project state.

## Operating Rules
- Keep mutable runtime job state only in the backend job registry.
- Keep `contract/annotation-pack/v0/schema/annotation-pack.schema.json` as the sole Pack wire authority. Generated Python/runtime copies and the staged GitHub Pages projection are byte-checked derivatives and must never become a second source of truth; the schema IRI is not live until default-branch deployment and served-byte verification.
- Keep minimal v0 Pack/package content limited to the W3C/EPUB/Dublin Core wire: exact EPUB NIH identity plus Highlight/Note TextQuote and TextPosition anchors. There is no project JSON-LD context or namespace; local pointer/report companions stay outside `annotations.json` and `.annotations`.
- Keep the producer-neutral information responsibility contract in the canonical Annotation Pack README. Private mechanism versions may change, but every supported adapter must map into the same neutral annotation choice; source/publication facts and exporter-derived W3C fields must not be pushed into the Agent contract.
- Keep explicit Annotation Pack publications under `output/<book_id>/public/annotation-packs/`. The selected immutable revision is local public-safe content output only; it is not job, checkpoint, resume, mechanism, source-ledger truth, or evidence of an available HTTP/API surface.
- Keep the append-only local ledger as runtime-observability fact truth and Phoenix/OpenTelemetry traces as derived operational views; job/checkpoint/runtime artifacts remain lifecycle truth.
- Keep durable current state in `docs/current-state.md`, not in `docs/agent-handoff.md`.
- Keep workspace task routing in `docs/tasks/registry.*`, and link each task outward to detailed trackers, truth docs, decisions, jobs, and evidence.
- Keep the Memory / Planning optimization design chain in its initiative-local implementation workspace. It is implementation-facing handoff material for the existing `attentional_v2` mechanism and does not replace stable mechanism or evaluation docs; stable behavior changes still need promotion to the relevant stable docs.
- Keep the evaluation run ledger as an operational index of what ran and where artifacts live; only promote reviewed / selected evidence into the evidence catalog.
- If a piece of information matters after the current chat ends, it must be stored in one of the canonical locations above.
- If the same durable fact appears in both `docs/agent-handoff.md` and a canonical file, the canonical file wins.
